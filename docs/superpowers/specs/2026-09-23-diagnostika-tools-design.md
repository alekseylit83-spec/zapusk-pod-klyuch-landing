# Два опросника-демо: бриф для открытия и диагностика для действующего заведения

**Дата:** 2026-09-23
**Статус:** утверждено, готово к плану реализации

## Контекст

Лендинг (`index.html`) продаёт услугу «запуск заведений под ключ» в Минске
(см. `PRD.md`, идея 0 в `yc-rfs/product-ideas.md`). Три варианта маленького
интерактивного демо для лендинга были предложены и зафиксированы в
`demo.md`; в диалоге с пользователем решение эволюционировало в собственный
дизайн с двумя независимыми направлениями вместо одного из трёх вариантов.

## Ограничения (не меняются, унаследованы от исходного задания)

Страница живёт на GitHub Pages:

- только статика: HTML, CSS, JS в браузере;
- никакого сервера, backend, базы данных;
- никаких API-ключей и обращений к платным сервисам;
- никаких библиотек и шрифтов из интернета;
- никакой сборки — открыл файл, и всё работает, в том числе без интернета;
- работает с телефона.

Из этого следует ключевое архитектурное ограничение для отправки данных
(см. ниже, «Отправка в Telegram»): бот-токен нельзя зашивать в JS страницы —
его увидит любой через «просмотр кода», и токен можно будет использовать
для рассылки от имени бота кому угодно, не только автору сайта.

## Цель

Дать посетителю лендинга два самостоятельных инструмента, которые можно
пройти с телефона за 5–7 минут и получить ощутимый результат, который тут же
можно отправить автору в Telegram:

1. **«Я открываю заведение»** — сокращённый бриф по проекту.
2. **«У меня уже работает заведение»** — диагностика по восьми управленческим
   практикам плюс снимок текущего состояния объекта.

## Архитектурное решение

**Два отдельных самостоятельных HTML-файла**, а не один файл с общим
движком:

- `otkrytie.html` — бриф для тех, кто открывается.
- `diagnostika.html` — диагностика для действующего заведения.

Каждый файл содержит собственную копию общей механики (шаг-визард,
сохранение в `localStorage`, сборка итогового текста, отправка в Telegram).
Код не шарится между файлами — это осознанный выбор пользователя: с
раздельными файлами можно менять или снимать одно направление независимо от
другого, и у каждого может быть свой URL для рекламы. Требования к статике
(без сборки, открыл — работает) это не нарушает: дублирование общей
механики — по явному решению пользователя после того, как ему было прямо
озвучено, что это увеличивает объём кода, который надо держать синхронным
при будущих правках движка (визард, отправка в Telegram, стили). Правка
контента одного направления (списка вопросов) на второе не влияет.

Третий рассмотренный вариант — встраивание опросников прямо в `index.html`
— отклонён: перегружает лендинг.

## Общая механика (реализуется одинаково в обоих файлах)

### Шаг-визард

- Один вопрос/блок на экран, прогресс-бар сверху («Шаг 3 из 8»), кнопки
  «Назад» / «Далее».
- «Далее» ничего не блокирует — ответ можно пропустить (обязательных полей
  нет). Это сделано намеренно: инструмент демонстрационный, а не форма для
  реальной сделки, и потеря человека на обязательном поле дороже, чем
  неполный бриф.
- Стиль — тот же, что на лендинге: тёмный hero (`--bg-dark: #1c1a17`), акцент
  `--accent: #b5502d`, тот же шрифтовой стек и `border-radius`. Сверху —
  ссылка «‹ На главную» на `index.html`.

### Сохранение прогресса

- Ответы пишутся в `localStorage` на каждом шаге (ключ `otkrytie-answers-v1`
  и `diagnostika-answers-v1` соответственно), чтения/записи обёрнуты в
  `try/catch` — если `localStorage` недоступен (приватное окно), форма
  работает и без сохранения, просто без восстановления при повторном визите.
- При заходе на страницу, если в `localStorage` есть сохранённые ответы,
  форма стартует с того шага, на котором человек остановился, а не с начала.

### Финальный экран

- Показывает собранный читаемый текст (человек видит, что именно уйдёт
  автору, до отправки).
- Кнопка **«Отправить вам в Telegram →»**: открывает
  `https://t.me/AlekseyResto?text=<encodeURIComponent(текст)>`.
- Кнопка **«Скопировать текст»** (через `navigator.clipboard`, с fallback на
  `document.execCommand('copy')` для старых браузеров) — на случай, если
  Telegram не установлен или deep link не сработал на конкретном устройстве.
- Короткая честная строка под кнопками: «Ответы остаются в этом окне, пока
  вы не нажмёте «Отправить» — тогда откроется Telegram с готовым текстом, и
  уходит только то, что вы подтвердите».

### Отправка в Telegram — почему deep link, а не бот

Полностью автоматическая фоновая отправка потребовала бы Telegram
bot-токена в JS-коде страницы. Токен в исходнике статической страницы виден
любому, кто откроет «просмотр кода», и может быть использован для рассылки
от имени бота на сторону — это прямое нарушение ограничения «никаких
API-ключей, которые видит любой, кто откроет исходный код». Backend-прокси,
который спрятал бы токен, запрещён отдельным ограничением «никакого
сервера». Поэтому выбран deep link `t.me/<username>?text=...`: он не требует
токена, открывает Telegram (приложение или веб) с уже вставленным текстом, и
отправляет только то, что посетитель подтвердил нажатием «Отправить» внутри
самого Telegram. Юзернейм `AlekseyResto` взят из существующей кнопки
«Написать в Telegram» на лендинге (`index.html:485`).

## Направление 1: `otkrytie.html` — бриф для открытия

Источник контента — реальный бриф пользователя (этапы 1, 2, 4, вставленные в
диалог), сокращённый до 8 шагов. Полная версия брифа с точными суммами
аренды/депозита и техническим чек-листом помещения (вентиляция, мощность и
т.д.) в демо не входит — она используется отдельно, в реальной работе с
клиентом после первого контакта.

Шаги визарда:

1. **Зачем открываете** (один выбор): инвестиционный проект / бизнес, которым
   хотите заниматься лично / создание своего бренда / проект для продажи /
   имиджевый проект / семейный бизнес / другое (текст).
2. **Что хотите открыть** (один выбор): ресторан / бар / паб / кафе / бистро /
   ночной клуб / ресторан + бар / другое (текст).
3. **Концепция одной фразой** (три коротких текстовых поля, собираются в
   одно предложение): «Мы создаём **___** для **___**, где гости получают
   **___**».
4. **Есть ли уже помещение** (да/нет); если да — три дополнительных поля:
   адрес/район (текст), площадь в м² (число), посадочные места (число).
5. **Если помещения ещё нет — что важно при выборе локации** (мультивыбор):
   пешеходный трафик / автомобильный трафик / туристический поток / офисный
   кластер / жилой район / ночная жизнь / торговый центр. Шаг пропускается,
   если на шаге 4 выбрано «да».
6. **Насколько лично готовы участвовать в операционке** (один выбор):
   полностью управляю сам / участвую стратегически / не участвую в
   операционке / пока не определился.
7. **Желаемый срок выхода на операционную прибыль** (один выбор, диапазоны —
   точное число неудобно вводить с телефона): до 6 месяцев / 6–12 месяцев /
   12–24 месяца / пока не знаю.
8. **Планируется сеть** (один выбор): одна самостоятельная точка / несколько
   собственных заведений / сеть / франшиза в дальнейшем / пока не
   определено.

Итоговый текст для Telegram — пример:

```
Бриф по проекту (с сайта, направление «открытие»)

Зачем открывает: создание своего бренда
Формат: бар
Концепция: Мы создаём бар с авторским коктейльным меню для
   молодой аудитории 25–35, где гости получают формат вечернего
   события, а не просто напитки
Помещение: есть — центр, 180 м², 60 посадочных мест
Участие в операционке: участвует стратегически
Срок выхода на операционную прибыль: 6–12 месяцев
Сеть: пока одна точка
```

Поля, оставленные пустыми (шаг пропущен), в итоговый текст не попадают.

## Направление 2: `diagnostika.html` — диагностика для действующего заведения

### Раздел А — управленческие практики (шкала)

Один и тот же вопрос применяется к каждому из семи пунктов: «Насколько это
под контролем без вашего личного участия?» Варианты ответа и их вес для
итоговой сводки:

- «Под контролем без меня» → зелёный
- «Держится, пока слежу лично» → жёлтый
- «Не измеряю / не слежу» → жёлтый
- «Не под контролем» → красный

Пункты:

1. Фудкост и маржинальность меню
2. Планирование смен и текучка персонала
3. Стандарты и чек-листы открытия/закрытия смены
4. Финансовая отчётность перед вами (P&L, кассовые разрывы)
5. Найм и обучение новых сотрудников
6. Маркетинг и заполняемость / повторные визиты
7. Меню разбирается по ABC-анализу (что держит маржу, что просто занимает
   место в меню)

(Пункты «разрешительная документация» и «оборудование и техобслуживание» из
черновика дизайна исключены по решению пользователя.)

### Раздел Б — план-факт по выручке

Отдельное числовое поле, не часть шкалы: **«На сколько процентов факт по
выручке отличается от плана в последнем завершённом месяце?»** — числовой
ввод со знаком (например, `-15` или `+5`), подпись «%» рядом с полем.
Значение попадает в итоговый текст как есть, без цветовой оценки — это
цифра для разговора, не диагностический признак.

### Раздел В — снимок объекта (факты, без оценки)

- **Режим работы** — текстовое поле, например «Пн–Вс, 10:00–23:00».
- **Формат меню** — мультивыбор: завтраки / бранчи / бизнес-ланч (обеды) /
  основное меню / бар и напитки / десерты / другое.
- **Сильные дни недели** — мультивыбор Пн–Вс.
- **Слабые дни недели** — мультивыбор Пн–Вс (те же семь чекбоксов, отдельный
  шаг).
- **Заполняемость по часам** — короткое текстовое поле, например «полно
  Пт–Сб 19:00–22:00, пусто днём в будни». Почасовая аналитика по кассовым
  данным сюда не входит: это не то, что человек честно заполнит в форме на
  телефоне за 5 минут без выгрузки из кассы.

### Итоговый экран

Сводка над текстом для Telegram:

- «Под контролем: N из 7», «Держится на вас лично или не измеряется: N»,
  «Не под контролем: N» — по разделу А;
- **«Главный риск:»** — первый пункт раздела А, отмеченный красным, если
  такой есть; если красных нет, но есть жёлтые — берётся первый жёлтый с
  формулировкой «то, что развалится в ваш первый отпуск»; если все
  зелёные — «Явных слабых мест по этим семи пунктам не видно»;
- ниже — список всех семи пунктов с цветовой меткой, план-факт по выручке,
  снимок объекта (раздел В).

Пример итогового текста для Telegram:

```
Диагностика заведения (с сайта, направление «действующее»)

Под контролем без меня: 3 из 7
Держится на мне / не измеряю: 3
Не под контролем: 1

Главный риск: найм и обучение — не под контролем

Фудкост и маржинальность: под контролем без меня
Смены и текучка: держится, пока слежу лично
Стандарты и чек-листы смены: под контролем без меня
Финансовая отчётность: не измеряю
Найм и обучение: не под контролем
Маркетинг и заполняемость: держится, пока слежу лично
ABC-анализ меню: под контролем без меня

План-факт по выручке: -12%

Режим работы: Пн-Вс, 11:00-00:00
Формат меню: бизнес-ланч, основное меню, бар
Сильные дни: пятница, суббота
Слабые дни: понедельник, вторник
Заполняемость по часам: полно Пт-Сб 19:00-23:00, пусто днём в будни
```

## Вход с лендинга (`index.html`)

Новый короткий блок добавляется перед существующей финальной секцией
«Что дальше» (`index.html`, секция с `id="contact"`). Две кнопки в стиле
`.btn`, ведущие на `otkrytie.html` и `diagnostika.html` с подписями «Я
открываю заведение →» и «У меня уже работает заведение →». Финальная секция
с прямой ссылкой «Написать в Telegram» остаётся без изменений — как общий
запасной контакт для тех, кто не хочет проходить опросник.

## Не входит в объём

- Изменение текста и структуры остального `index.html`, кроме добавления
  одного нового блока с двумя кнопками.
- Полная (не сокращённая) версия брифа с точными финансовыми полями.
- Реальный расчёт ABC-анализа или почасовой аналитики по вводимым данным —
  оба поля остаются на уровне «факт со слов человека», без вычислений.
- Общий движок/шаринг кода между `otkrytie.html` и `diagnostika.html` —
  сознательно отклонено (см. «Архитектурное решение»).

## Тестирование

Ручная проверка (файлы статические, автоматических тестов не пишем):

- Оба файла открываются напрямую с диска (`file://`) без ошибок в консоли.
- Прохождение визарда от начала до конца в каждом направлении, включая все
  ветвления (шаг 5 в `otkrytie.html` пропускается при «да» на шаге 4).
- Прогресс сохраняется в `localStorage` и восстанавливается при перезаходе;
  форма не ломается, если `localStorage` недоступен (эмулировать приватным
  окном или блокировкой в DevTools).
- Кнопка «Отправить в Telegram» формирует корректный deep link с
  корректно закодированным текстом (проверить на пустых и на всех
  заполненных полях).
- Кнопка «Скопировать текст» кладёт в буфер обмена текст, совпадающий с
  тем, что показан на экране.
- Обе страницы и новый блок на лендинге проверяются на экране шириной
  375px (iPhone SE) и в тёмной/светлой схеме, если лендинг её поддерживает.
